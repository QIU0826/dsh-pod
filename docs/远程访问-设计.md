# 远程/手机访问设计（为连接手机远程操作打地基）

> 2026-09-06：参照 dsh-web/dsh-remote-web-ui 的成熟机制（二维码配对 + 一次性令牌 +
> 可撤销设备会话 + 门控通道 + cloudflared 固定域名隧道），为 dsh-pod standalone 控制台
> 规划同一形态的远程访问。本文是设计基线——实现分片落地，每片保持 fail-closed。

## 1. 目标形态

手机扫码 → 一次性令牌配对 → 手机浏览器获得**同一个** standalone 控制台（桌宠房间/
对话/审批/看板），竖屏触控适配；电脑经 LAN/隧道走门控通道；配对可撤销、令牌会过期。

## 2. 已就绪的地基（本设计直接复用）

| 已有 | 位置 | 在远程形态中的角色 |
|---|---|---|
| Bearer token 门禁 | standalone `guard()`（token 缺省 loopback-only，非 loopback 必须 token） | 远程通道鉴权的基底——配对设备会话将替换「共享静态 token」为「逐设备凭据」 |
| 非 loopback fail-closed | `listenStandalone`（绑 0.0.0.0 无 token 拒绝启动） | 防止裸奔暴露到局域网/公网 |
| `/pet-assets/` 同源静态面 | 2026-09-05 | 远程模式下桌宠资产同源可达（无需外网） |
| SSE 事件流（含 AG-UI 格式） | `/api/dsh-pod/events/stream` | 手机端实时状态推送已就绪 |
| A2A push webhook | `a2a-push.ts` | 远程「任务完成通知到手机」可复用同一投递基建 |
| pair-access 信任栅栏参考 | dsh-web `pair-access.ts`（loopback 恒过 + 配对 cookie 附加放行） | 守卫扩展的直接蓝本 |

## 3. 分片路线

### 片 A：设备会话与配对端点族（核心）——✅ 已落地（2026-09-06）
-  PairingStore：一次性令牌（同时仅一枚、TTL 10min、配对即作废）、
  设备会话（deviceId+secret 恒时校验、UA 推断短名、逐设备撤销）、atomicWrite 持久化
  （.bak 崩溃窗口自愈，全坏时空库重配对不阻塞启动）
- 端点族（standalone）：POST /api/pair/mint|accept|revoke、GET /api/pair/devices——
  mint/revoke/devices 物理 loopback-only（对齐 dsh-remote-web-ui「铸造面仅限本机」）；
  accept 是唯一非回环可达端点（凭一次性令牌自证），Set-Cookie HttpOnly+SameSite=Lax 30 天
- guard 扩展：非 loopback 第二凭据路径——Cookie pod-device=<id>.<secret> 恒时校验放行；
  loopback 恒过路径不变；CLI --pairing 显式开启（既有 fail-closed 不放松）
- 测试 tests/pairing.test.ts +9（含真实 HTTP 全链路：mint→accept→凭 Cookie 访问受保护路由；
  devices 列表不泄露凭据）
- `PairSession`：`{ deviceId, name(UA 推断), pairedAt, lastSeenAt, revoked }` 存
  `<dataDir>/pairing.json`（atomicWrite 同款）。
- 端点族（**铸造面 loopback-only**，对齐 dsh-web 纪律）：
  - `POST /api/pair/mint` → 一次性令牌 + 配对 URL（含 QR 内容串）；同时仅一枚有效令牌，
    重复铸造使旧令牌失效；令牌 TTL（默认 10 分钟）。
  - `POST /api/pair/accept`（凭令牌，无 Cookie）→ 换发设备凭据（HttpOnly Cookie 或
    `X-Pod-Device` 头）。
  - `POST /api/pair/revoke`（loopback-only）→ 逐设备/全部撤销。
- 守卫扩展点：`guard()` 增加一条放行分支——「持有效设备会话的非 loopback 请求」
  （对齐 pair-access 的 loopback 恒过 + 配对放行双路）。

### 片 B：LAN 绑定与隧道

### 片 B/C 客户端面——✅ 已落地（2026-09-06）

## 4. 安全模型（对齐 dsh-web，逐条落地）

1. 配对令牌一次性、限时、同时仅一枚；扫码转手可完成配对。
2. 设备会话是**完全控制凭据**（能 abort/审批/合并）——逐设备可撤销、列表可见、
   凭据（设备 id + 原始 UA）永不渲染到 UI。
3. 铸造/撤销端点物理 loopback-only；LAN 打开的桌面浏览器看到「配对面板仅限本机」。
4. 回环（127.0.0.1）直连不受影响——本地体验零变化。
5. 远程通道与 `/api/pair/*`、更新面物理分离（后者永不暴露到非回环）。

## 5. 非目标（明确排除）

- 不做第二套移动版界面——与 dsh-web 同一判断：两端运行同一控制台，避免漂移。
- 不做账号体系——单用户自托管场景，设备会话即身份。
- 不在无 token 时允许任何非回环来源——既有 fail-closed 纪律不放松。
