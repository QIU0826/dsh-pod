舱员名册 · 六角色系统

全员同一套身体骨架与兜帽轮廓（形态一致），六个主题各自替换：帽顶饰 / 帽耳 / 背后尾饰 / 配色 / 胸章 / 全部动作道具（元素不同）。建议厂商绑定可用 localStorage["dsh-pod.petCharacterMap"] 重绑，未注册厂商默认落到猫·麻薯。

许可口径：六角色为自产角色包（建议 MIT，pet.json 如实填 author/license）；仅 dsh 位沿用内置鲸鱼娘血统（BSD-3）。生态角色 miku / ouo-neko / whale-refined（MIT）继续可用——v2 轨道是超集，旧角色未注册的轨道自动 fallback，互不影响。

动作 × 事件映射 · 十二轨道总表

前 7 行对齐现有 pet-room.ts slotPhase() 的七相位词汇（旧角色不注册新轨道则走 fallback，行为不变）；后 5 行是 v2 新增的事件驱动轨道。轨道名即 frames2d 目录名，帧命名 <角色>-pet-<轨道><序号>.webp。

实现口径与已知边界

本预览器是美术规格的活参考（SVG + CSS 演示每个轨道该画什么），不是渲染引擎替代——生产端仍走 frames2d/sprite2d 双契约。

维度口径
轨道帧数循环轨 4–8 帧；一次性轨（error 蹲姿前段 / happy / carrying 放箱 / 惊醒）3–5 帧 + fallback idle
帧尺寸192×208 webp 透明底（或整倍率），与图集系同比例可混排；帧间头部大小与地平线一致
时长解析frameMs[] > 文件名 _<ms> 后缀 > defaultFrameMs（缺省 200ms）——沿用 v1 引擎，无需改代码
phases 映射pet.json v2 的 phases 段把 7 相位指到新轨道；5 条新事件轨道由编排层在对应事件窗口内直接点名播放
fallback 链未注册轨道 → idle（引擎既有行为）；error 轨播完停在末帧直到相位离开 failed
降级prefers-reduced-motion 时全部轨道静态化（本预览器同款行为）
与 v1 规格的关系：v1 的六轨（idle/work/drag/success/fail/angry）分别由 idle / think+type+build（work 拆分）/ type+build（drag 并入 tool 语义）/ happy / error / 蜷睡前的惊醒帧 承接；angry 保留给交叉审查对峙编排（reviewDuels）继续使用。历史决策不改写，v2 以扩展轨道集的方式追加。
