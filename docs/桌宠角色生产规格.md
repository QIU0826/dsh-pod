# 桌宠角色生产规格（三视图 → 帧动画）

> 目的：给「每个 AI 一只专属小萝莉」的角色生产定标准——按本规格生成的素材放进资产基址
> 即被 dsh-pod 桌宠房间直接加载（frames2d 契约，与 dsh-web/dsh-pet 生态 drop-in 兼容）。
> 工程侧已就绪的部分见文末「已就绪清单」；本文件是美术生成的唯一口径。

## 1. 两类渲染契约（先选对）

| 契约 | 素材形态 | 适用 | 本仓库引擎 |
|---|---|---|---|
| **frames2d**（推荐新角色用） | 每个动作一个目录、每帧一张 webp | 帧数多、动作细腻的新角色 | `pet-frames2d.ts` |
| sprite2d | 单张图集（192×208/帧 × 8 列 × 9 行） | 兼容老鲸鱼娘系（ouo-neko / whale-refined） | `pet-sprite.ts`（已泛化） |

## 2. frames2d 目录布局

```
<base>/<character>/
  pet.json                 # 清单（见 §4 模板）
  thumb/                   # frames2d.dir（建议就叫 thumb）
    idle/    miku-pet-stop1.webp ...   # 循环轨：呼吸待机
    work/    ...                        # 循环轨：干活（thinking/tool/review 共用）
    drag/    ...                        # 循环轨：被拖拽/工具调用
    success/ ...                        # 非循环：任务完成庆祝 → fallback idle
    fail/    ...                        # 非循环：出状况 → fallback idle
    sleep/   ...                        # 循环轨：mission 暂停时趴窝（可选）
    angry/   ...                        # 非循环：交叉审查被盯（可选，对峙编排用）
```

- 帧文件名：`<角色名>-pet-<语义名><序号>.webp`；**建议帧数 4–8 帧/轨道**。
- 每帧建议 **192×208（或整倍率）**，透明背景；与图集系角色同比例可混排。
- 时长解析：`frameMs[]` > 文件名 `_<ms>` 后缀 > 清单 `defaultFrameMs`（缺省 200ms）。

## 3. 最小可行轨道集（MVP 六轨）

新角色至少产出：**idle（4帧）/ work（4帧）/ drag（4帧）/ success（3帧）/ fail（3帧）/ angry（3帧）**。
缺哪个轨道，运行时自动回落 idle——不炸渲染，但会缺表情。

## 4. pet.json 模板（frames2d）

```json
{
  "petManifestVersion": 2,
  "id": "zcode-girl",
  "displayName": "Zcode 娘",
  "description": "zcode 专属小萝莉：智谱蓝主色 + 终端元素发饰。",
  "author": "<你的署名>",
  "license": "MIT",
  "renderer": "frames2d",
  "frames2d": {
    "dir": "thumb",
    "defaultFrameMs": 200,
    "phases": { "idle": "idle", "thinking": "work", "tool": "drag", "review": "work", "done": "success", "failed": "fail" },
    "tracks": {
      "idle":    { "frames": ["zcode-pet-idle1.webp", "zcode-pet-idle2.webp", "zcode-pet-idle3.webp", "zcode-pet-idle4.webp"] },
      "work":    { "frames": ["zcode-pet-work1.webp", "zcode-pet-work2.webp", "zcode-pet-work3.webp", "zcode-pet-work4.webp"] },
      "success": { "frames": ["zcode-pet-success1.webp", "zcode-pet-success2.webp", "zcode-pet-success3.webp"], "loop": false, "fallback": "idle" },
      "fail":    { "frames": ["zcode-pet-fail1.webp", "zcode-pet-fail2.webp", "zcode-pet-fail3.webp"], "loop": false, "fallback": "idle" },
      "angry":   { "frames": ["zcode-pet-angry1.webp", "zcode-pet-angry2.webp", "zcode-pet-angry3.webp"], "loop": false, "fallback": "idle" }
    }
  }
}
```

`phases` 是 dsh-pod 工作状态 → 轨道的映射（idle/thinking/tool/review/waiting/done/failed 七态）。

## 5. 生成流程（三视图 → 动作帧）

1. **三视图定稿**：正/侧/背全身立绘，Q 版 2.5 头身，透明底；要求「一眼认出对应 AI」——
   品牌色 + 品牌物种 + 专属道具三件套齐全。贴纸线四角色（见 §5.1）口径：
   - **Claude 娘**（claude-girl）：橙→珊瑚粉渐变长发、头顶两根猫头鹰羽冠、棕色猫头鹰翅状耳、
     琥珀色大眼、背后小翅膀、蓬松橙尾羽；趴在写满手写笔记的硬皮笔记本上（羽毛笔涂鸦）；
     迷你分身站羽毛上挥手。品牌色 `#F0784D`，线稿 `#7A3E22`。
   - **Codex 娘**（codex-girl）：翠绿→薄荷绿短发、一根呆毛、白色猫耳（绿耳尖）、绿色猫眼、
     深灰连帽卫衣（帽上猫耳开孔）、绿猫尾白尖；趴在银色笔记本电脑上（绿终端代码+闪烁光标），
     键盘散落小齿轮；迷你分身坐终端黑框窗口探头。品牌色 `#1FC16B`，线稿 `#0B3D2E`。
   - **OpenCode 娘**（opencode-girl）：深紫→靛蓝长发、卷曲呆毛、紫狐耳（浅紫内耳）、
     紫罗兰大眼、黑色短款连帽衫、蓬松紫狐尾白尖、脖子挂六边形开源徽章吊饰；趴在多标签页
     黑终端窗口上（紫命令行提示符）；迷你分身举 `>_` 牌探头。品牌色 `#7C5CFC`，线稿 `#262057`。
   - **DeepSeek 娘**（deepseek-girl，风格基准）：深蓝→天蓝长发、卷呆毛、鲸鱼鳍状小耳、
     蓝色大眼、深蓝吊带连体衣、**完整深蓝鲸尾+浅蓝尾鳍（非腿）**、腰间金环扣；趴在蓝色
     纹理厚书上；迷你分身趴在小鲸尾上挥手。品牌色 `#2F7FD6`，线稿 `#12306B`。
   - SVG 平涂线旧角色：zcode/GLM 智谱蓝 `#2E6BE6`+终端、ark 品牌蓝+火山、dsh 青+六边形鲸群、
     gemini 蓝紫波浪发+四色四芒星。
2. **动作帧派生**：以三视图的正视图为基准逐帧改姿态（眨眼/挥手/干活/叉腰/庆祝/趴下），
   同轨道内保持头部大小与地平线一致——帧间跳动是流畅度杀手。
3. **导出**：每帧独立 webp（192×208 透明底），按 §2 命名放目录。
4. **注册**：写 pet.json（§4 模板），把目录放到资产基址下，或在
   `localStorage["dsh-pod.petCharacterMap"]` 里 `{"claude": "<id>"}` 换装。

### 5.1 贴纸线自产管线（`scripts/pet-assets-sticker.mjs`，2026-09-07）

四角色（claude/codex/opencode/deepseek）不走外部三视图，由脚本从**单张贴纸风主视觉**
全自动派生六轨连接帧，保证「同一母版参数化变换、地平线恒定、帧间零跳动」：

1. **SVG 主视觉**（脚本内 `heroXxx()` 手工绘制 720×720 白底 SVG）：Q 版 chibi 少女、
   大头小身、半睁眼慵懒托腮、趴姿道具、左上角迷你分身、黄四角星装饰、白色粗描边贴纸风。
   纪律：每个形状闭合描边（`stroke-linejoin:round`）；白色/浅色部件（白猫耳、尾尖、
   本子内页、终端弹窗、齿轮中心孔）必须被深色描边或彩色填充完全围住，否则下一步去白底
   会把内部白吃通。
2. **去白底**：Chrome CDP（端口 9338）里 canvas 像素洪泛——边缘连通且近白（R/G/B>232 且
   max-min<26）的像素 alpha 置 0，两轮收缩去白边毛边，再按 alpha 包围盒裁切。
3. **白描边重建**：alpha 膨胀（R=max(6, w*0.016)）铺白，贴回主体，得到贴纸式白色外描边。
4. **配件层**：按轨道叠 sparkle 四角星 / HUD 终端芯片（work）/ 汗滴（drag）/ 红色怒气标记
   （angry）/ 速度线；六轨共 21 帧（idle4/work4/drag4/success3/fail3/angry3），全部由
   母版绕底部锚点 (96,204) 做位移/倾斜/缩放变换；success 起跳帧 `fs:0.9` 整体略缩防呆毛/
   羽冠顶部裁切。
5. **产物**：`demo-data/pet-assets/<id>/` 下 192×208 透明底 webp 帧（`<short>-pet-<track><n>.webp`）、
   460px `hero.webp`、`pet.json`（六轨 + phases 映射，非循环轨 `loop:false + fallback:'idle'`）。

> 注：文生图接口需 IDE 会话认证，外部脚本不可用（永远 302 到占位图），故主视觉为 SVG 手绘；
> 脚本里 `--fetch` 路径保留但非主路径。改 SVG 后需删除 `%TEMP%/dsh-pod-pet-heroes/<id>.png`
> （注意残留占位 JPEG 魔数 FFD8 伪装成 .png 的陷阱）才会重新渲染。

## 6. 切片/校验脚本

```
node scripts/pet-asset-slice.mjs <帧目录> --id <角色id> --name <显示名> [--out <输出目录>]
```
校验帧名安全、尺寸一致、生成 pet.json（含轨道回退声明）；`pet-asset-resolve.mjs`
负责把生态"列目录式"清单解析成显式帧表。

本仓库自产角色两条生成管线（无需外部美术素材）：

```
node scripts/pet-assets-sticker.mjs     # 贴纸线（见 §5.1）：claude/codex/opencode/deepseek
node scripts/pet-assets-generate.mjs    # SVG 平涂线：zcode/ark/dsh/gemini
```
