# 桌宠角色生产规格（三视图 → 帧动画）

> 目的：给「每个 AI 一只专属小萝莉」的角色生产定标准——按本规格生成的素材放进资产基址
> 即被 dsh-pod 桌宠房间直接加载（frames2d 契约，与 dsh-web/dsh-pet 生态 drop-in 兼容）。
> 工程侧已就绪的部分见文末「已就绪清单」；本文件是美术生成的唯一口径。

## 1. 两类渲染契约（先选对）

| 契约 | 素材形态 | 适用 | 本仓库引擎 |
|---|---|---|---|
| **frames2d**（推荐新角色用） | 每个动作一个目录、每帧一张 webp | 帧数多、动作细腻的新角色 | `pet-frames2d.ts` |
| sprite2d | 单张图集（192×208/帧 × 8 列 × 9 行） | 兼容老鲸鱼娘系（ouo-neko / whale-refined） | `pet-sprite.ts`（已泛化） |

## 2. frames2d 目录布局

```
<base>/<character>/
  pet.json                 # 清单（见 §4 模板）
  thumb/                   # frames2d.dir（建议就叫 thumb）
    idle/    miku-pet-stop1.webp ...   # 循环轨：呼吸待机
    work/    ...                        # 循环轨：干活（thinking/tool/review 共用）
    drag/    ...                        # 循环轨：被拖拽/工具调用
    success/ ...                        # 非循环：任务完成庆祝 → fallback idle
    fail/    ...                        # 非循环：出状况 → fallback idle
    sleep/   ...                        # 循环轨：mission 暂停时趴窝（可选）
    angry/   ...                        # 非循环：交叉审查被盯（可选，对峙编排用）
```

- 帧文件名：`<角色名>-pet-<语义名><序号>.webp`；**建议帧数 4–8 帧/轨道**。
- 每帧建议 **192×208（或整倍率）**，透明背景；与图集系角色同比例可混排。
- 时长解析：`frameMs[]` > 文件名 `_<ms>` 后缀 > 清单 `defaultFrameMs`（缺省 200ms）。

## 3. 最小可行轨道集（MVP 六轨）

新角色至少产出：**idle（4帧）/ work（4帧）/ drag（4帧）/ success（3帧）/ fail（3帧）/ angry（3帧）**。
缺哪个轨道，运行时自动回落 idle——不炸渲染，但会缺表情。

## 4. pet.json 模板（frames2d）

```json
{
  "petManifestVersion": 2,
  "id": "zcode-girl",
  "displayName": "Zcode 娘",
  "description": "zcode 专属小萝莉：智谱蓝主色 + 终端元素发饰。",
  "author": "<你的署名>",
  "license": "MIT",
  "renderer": "frames2d",
  "frames2d": {
    "dir": "thumb",
    "defaultFrameMs": 200,
    "phases": { "idle": "idle", "thinking": "work", "tool": "drag", "review": "work", "done": "success", "failed": "fail" },
    "tracks": {
      "idle":    { "frames": ["zcode-pet-idle1.webp", "zcode-pet-idle2.webp", "zcode-pet-idle3.webp", "zcode-pet-idle4.webp"] },
      "work":    { "frames": ["zcode-pet-work1.webp", "zcode-pet-work2.webp", "zcode-pet-work3.webp", "zcode-pet-work4.webp"] },
      "success": { "frames": ["zcode-pet-success1.webp", "zcode-pet-success2.webp", "zcode-pet-success3.webp"], "loop": false, "fallback": "idle" },
      "fail":    { "frames": ["zcode-pet-fail1.webp", "zcode-pet-fail2.webp", "zcode-pet-fail3.webp"], "loop": false, "fallback": "idle" },
      "angry":   { "frames": ["zcode-pet-angry1.webp", "zcode-pet-angry2.webp", "zcode-pet-angry3.webp"], "loop": false, "fallback": "idle" }
    }
  }
}
```

`phases` 是 dsh-pod 工作状态 → 轨道的映射（idle/thinking/tool/review/waiting/done/failed 七态）。

## 5. 生成流程（三视图 → 动作帧）

1. **三视图定稿**：正/侧/背全身立绘，Q 版 2.5 头身，透明底；要求融入对应 AI 公司元素
   （Claude：陶土橙 #D97757 + 星芒；zcode/GLM：智谱蓝 #2E6BE6 + 终端元素；OpenCode：暖橙 +
   命令行窗口元素；Codex：黑绿极客风）。
2. **动作帧派生**：以三视图的正视图为基准逐帧改姿态（眨眼/挥手/干活/叉腰/庆祝/趴下），
   同轨道内保持头部大小与地平线一致——帧间跳动是流畅度杀手。
3. **导出**：每帧独立 webp（192×208 透明底），按 §2 命名放目录。
4. **注册**：写 pet.json（§4 模板），把目录放到资产基址下，或在
   `localStorage["dsh-pod.petCharacterMap"]` 里 `{"claude": "<id>"}` 换装。

## 6. 切片/校验脚本

```
node scripts/pet-asset-slice.mjs <帧目录> --id <角色id> --name <显示名> [--out <输出目录>]
```
校验帧名安全、尺寸一致、生成 pet.json（含轨道回退声明）；`pet-asset-resolve.mjs`
负责把生态"列目录式"清单解析成显式帧表。
