# ACP 消歧义 + Zed ACP 重估（2026-09-01）

> 触发：待办 P3「ACP 消歧义 + 重估 Zed ACP」。项目内外提「ACP」时存在**两个同名不同义**
> 的协议，本文把三者（MCP / A2A / 两种 ACP）的关系钉死，避免后续会话再混淆，
> 并给出 Zed ACP 对 dsh-pod 的重估结论（记录、不排期）。

## 0. 一句话结论

- **IBM ACP（Agent Communication Protocol）已不存在**——2025-08 正式并入 A2A，其设计
  贡献（长任务持久状态 / 异步续跑 / webhook 进度回调 / REST 绑定）已全部融入 A2A v1.0。
- **Zed ACP（Agent Client Protocol）活着且在扩张**——它是「编辑器 ↔ AI 编码 agent」的
  标准（LSP for AI），与 agent 间通信的 A2A 是**互补不重叠**的两层。
- dsh-pod 站在 A2A 层（对外协议面已按 v1.0 对齐，见 `src/core/a2a.ts` + `src/a2a-push.ts`）；
  Zed ACP 是「编辑器内驾驶舱」形态，对 dsh-pod 属可选通道，**重估结论：成本极低、价值
  中等、无真实场景需求前不排期**。

## 1. 三个缩写的四层关系

| 协议 | 全称 | 解决什么 | 谁在推动 | 现状（2026-09 时点） |
|---|---|---|---|---|
| **MCP** | Model Context Protocol | agent ↔ 工具/数据（内层能力） | Anthropic，2024-11 开源 | 事实标准；2025-12 随 AAIF 纳入 Linux Foundation 治理 |
| **A2A** | Agent2Agent Protocol | agent ↔ agent 协作（外层编排） | Google 发起，2025-06 捐 Linux Foundation；2025-08 并入 IBM ACP | **v1.0 于 2026-03-12 发布**（首个 production-ready） |
| **ACP（IBM）** | Agent Communication Protocol | 长任务、状态化、异步的 agent 编排 | IBM Research（BeeAI 平台），2025-03 | **已并入 A2A**（2025-08-29 公告），独立标准终止 |
| **ACP（Zed）** | Agent Client Protocol | 编辑器 ↔ AI 编码 agent（驾驶舱 UI 层） | Zed 发起 + JetBrains 联合开发，Apache-2.0 | 活跃；ACP Registry 已上线（2026-01，与 JetBrains 联合） |

**记忆口诀**：MCP 给 agent 能力，A2A 让 agent 协作，Zed-ACP 让编辑器开 agent。

## 2. IBM ACP → A2A 合并时间线（已尘埃落定）

- 2025-03：IBM Research 发布 ACP，作为开源平台 **BeeAI** 的运行内核。REST-native
  （OpenAPI 描述，curl/Postman 即可调）、任务持久化、异步续跑、webhook 进度回调。
- 2025-08-29：LF AI & Data 官方公告——ACP **正式并入 A2A**，IBM 加入 A2A 维护者社区，
  其代表进入 A2A Technical Steering Committee。ACP 以独立协议的身份**终止开发**。
- 吸收进 A2A 的 ACP 贡献：任务持久化、异步恢复、webhook 进度通知、REST 绑定易用性、
  运行时内省（runtime introspection）、生命周期管理（lifecycle）与群组通信模式。
- 2025-12-09：Linux Foundation 成立 **Agentic AI Foundation（AAIF）** 伞形治理——
  MCP（Anthropic）、goose（Block）、AGENTS.md（OpenAI）为三大初始项目；A2A 项目
  置于 AAIF 协调治理之下，与 MCP 维护者建立正式跨项目工作组（MCP↔A2A 互操作规范）。
- 2026-03-12：**A2A v1.0（tag v1.0.0）** 发布——三层规范结构（规范数据模型 protobuf /
  抽象操作 / JSON-RPC + gRPC + HTTP/REST 三绑定），首个 production-ready 版本。

**对 dsh-pod 的含义**：方案书/代码里凡是引用「ACP」概念（如 BeeAI、REST-native 长任务
webhook），在 2025-08 之后都应读作 **A2A v1.0 的特性**；我们的 `a2a-push.ts`（webhook
终态回调）与 `a2a.ts`（Agent Card / 任务状态机 / input-required / rejected）正是 ACP 并入
后 A2A v1.0 语义的直接实现——**没有走错方向，没有历史包袱**。

## 3. Zed ACP（Agent Client Protocol）—— 同名不同义

- 定位：**编辑器与 AI 编码 agent 之间的标准化接口**，建模于 LSP（2016 让语言能力与编辑器
  解耦的先例）——agent 实现一次，任何 ACP 兼容编辑器可用（Zed / JetBrains 全家桶 /
  Neovim 插件 / Emacs 插件 / marimo）。
- 形态：本地 agent 以**子进程**方式由编辑器拉起，JSON-RPC 2.0 over stdio（与 LSP 同传输）；
  远程 agent 走 HTTP/WebSocket。会话持久、双向请求（agent 可向编辑器要文件内容/权限）、
  token 级流式。
- 关键：**它是「UI/驾驶舱」层，不是 agent 间编排层**——一个 agent 在 Zed 里跑的同时可以
  通过 MCP 调工具（外层 ACP + 内层 MCP 并存是生产标准形态）。
- ACP Registry（2026-01 上线，Zed + JetBrains 内置）：**claude-code-acp（Zed 官方 adapter，
  Anthropic 未原生实现 ACP）、codex-acp（社区 adapter）、opencode、gemini-cli（首个原生）、
  copilot-cli（2026-01 原生预览）、goose、cline、cursor 等 25+ 已收录**——注册一次，全客户端可用。

## 4. 对 dsh-pod 的重估（Zed ACP）

| 维度 | 评估 |
|---|---|
| 是什么机会 | dsh-pod 的 worker 是 Claude Code / Codex / OpenCode 等 CLI agent，**全部已在 ACP Registry 可装**。用户在 Zed/JetBrains 里可开一个「外部 agent」线程直接驾驶单个 worker（看流式输出、调权限、给指令）——这是比终端更友好的**单 agent 驾驶舱**。 |
| 与现有架构的关系 | **不冲突、互补**：dsh-pod 以 headless CLI 拉 worker 跑 mission（A2A 层编排不变）；Zed ACP 只是把「单 worker 的内部运行」映射到编辑器 UI。就像同一个人既能被 API 调度、也能被 IDE 面板操作。 |
| 改动面 | **几乎为零**（宿主侧能力）：worker 照跑，多一层 UI 形态。真正要动的是「DSH 插件/独立控制台」侧是否要消费 ACP——这不是本仓库可验证的（宿主依赖，同 P0-1 剩余项）。 |
| 成本 | 极低（adapter 现成，注册即用）。 |
| 价值 | 中等偏可选：dsh-pod 的强项是**多 agent 编排的可观测性**（看板/DAG/上下文查看器），单 worker 驾驶舱与其重叠；除非出现「用户在编辑器里盯单个 worker 调参」的真实需求，否则 ROI 不如继续打磨 A2A 协议面（跨机/联邦）。 |

**重估结论（记录，不排期）**：Zed ACP 记为「现成通道、宿主侧接线项」——与 P0-1 的
「commander 每轮按 stage 注入完整 schema」同类（需 DSH 宿主配合，本仓库无法闭环验证）。
已列入本文件备查；若未来出现编辑器内驾驶舱需求，优先复用 ACP Registry 的现成 adapter，
不要自造协议。
