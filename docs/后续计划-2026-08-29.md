## 二、待办清单（按优先级）

### P1 —— 让成本与行为「看得见」（改动小、收益直接）

1. **byStage 接入前端与 Debrief**
   `Ledger.summary()` 已产出按任务类型（plan/implement/review/test/doc/research）的聚合，
   但 UI 与 Debrief 脚本目前只消费 `total_*`。接上后能直接回答「独立 review 这道质量门烧了多少」。
   落点：`src/web/` 账本面板、`scripts/` 的 bake-off 汇总。
2. **失败路径单独计数**
   重试/回滚/blocked→重派的 token 目前混在总账里。调研显示同一任务 token 用量存在 **30 倍方差**，
   主要来自失败路径。建议按 `attempts` 维度聚合，与阶段归因正交。
3. **信息增量式止损（early exit）**
   现有 watchdog 按**时间**触发（空闲/墙钟），缺「是否还在产生新信息」的维度。
   建议：连续 N 轮无新证据 / 同一测试重复失败 / 工具返回同类错误 → 切换策略或转人工。
   注意别误伤正常长任务，先用 experiments 灰度。

### P3 —— 协议与安全加固

8. **`docs/adapters.md` 补 ACP 消歧义，并重估 Zed ACP**（成本极低，优先做）
   「ACP」这个名字被两个互不相干的协议占用：IBM 的 Agent Communication Protocol 已于
   2025-08 并入 A2A；**Zed 的 Agent Client Protocol 独立存活**，是「AI 时代的 LSP」，
   JetBrains 全系支持，2026-01 上线 Registry（50+ agent）。
   文档现有表述（指 Zed 版）是对的，需要补的是消歧义说明。
   **更值得做的是重估它的机会**：Registry 里已有 `@zed-industries/claude-acp` 与 `codex-acp`，
   正是本项目用的员工形态——想进 Zed / JetBrains 做编辑器内驾驶舱，它是现成通道。
9. **mcp-gateway 补工具描述静态审查**
   MCP 的已知攻击面：tool poisoning（工具元数据藏恶意指令）与 Rug Pull（工具静默改写定义偷凭据）。
   当前 gateway 已有审批门 + 输出截断 + 审计，**缺下游工具描述的静态审查**。接第三方 server 前应补。
10. **satellite 协议考虑对齐 A2A Agent Card**（v0.4 方向，需权衡）
    `satellite-server.ts` 的 `/detect /start /events /kill /health` 语义接近 A2A 的能力发现 +
    任务委派 + 流式更新。对齐后可接 Salesforce Agentforce / ServiceNow Now Assist /
    Azure AI Foundry / Amazon Bedrock AgentCore；代价是接受外部 schema。**先记录方向，不急改**。
11. **AG-UI 参考（可选）**：项目的 SSE 帧（kind + payload）与 AG-UI 事件模型同构，
    若未来支持第三方前端，对齐能省一层适配。

## 三、方向建议（中长期，基于调研）

### 3.1 成本维度：从「预算闸」升级到「成本归因 + 边际收益」

现状已有：双熔断（美元 + token）、派发前预算短路、账本（tokens 实测 + equiv_usd 标注）。
缺的是**归因**与**边际判断**。Token Economics（浙大 + 阿里云，arXiv 2605.09104）给出的语言可以直接借用：
把 token 拆成 Input / Reasoning / Communication / External / Output 五类分别记账，
再看「每个 token 对目标质量的边际贡献是否超过它的真实成本」。
对应到 Pod 的可执行动作就是 P1 的三条。

### 3.2 上下文维度：继续走「结构化交付 + 引用传递」，别追 KV 复用

项目的 handoff（交接四件套）+ session-tiers（70% 阈值摘要）+ memory（主动策展）已经是论文推荐的组合，
且与 NOOA 的引用传递思路同源（实测 216,806 → 700 tokens，−99.68%）。**不建议大改**。

需要明确排除的方向：**跨 agent KV cache 复用**（KVComm / TokenDance / DroidSpeak）。
员工是跨 vendor 的独立 CLI 进程，拿不到 KV 层——这条应在方案书里写明排除，避免误投入。

### 3.3 协议维度：MCP 管工具、A2A 管 agent 间，分层叠加

调研的结论是这些协议**互补而非竞争**，工业界按层叠加。对 Pod 的含义：
- MCP 已落地（stdio + Streamable HTTP），继续做深（gateway 已在，补安全审查）；
- agent 间通信：自研 satellite 短期够用，中长期评估对齐 A2A；
- 前端事件流：与 AG-UI 同构，需要时再对齐；
- **编辑器侧的意外机会**：Zed ACP（Agent Client Protocol）与本项目的员工形态天然契合——
  Registry 里已有 Claude Code 与 Codex 的 ACP 实现。目前驾驶舱是自研 Web 控制台，
  若想让用户在 Zed / JetBrains 里直接看会话、任务与审批卡，这条通道的成本远低于自研 IDE 插件。
  **建议在 v0.4 排期时认真评估，别按「已并入 A2A」的错误前提把它划掉。**

写进方案书或对外材料前建议按标题检索原文复核。
