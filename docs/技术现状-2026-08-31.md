# 技术现状 · dsh-pod（2026-08-31）

> 现状快照，事实源是当前代码（commit 5da8bab 之后 + 本轮 P0-A/P0-B/P1 改动）。
> 架构导览见 `docs/ARCHITECTURE.md`；本文补齐 token 开销、通信协议、上下文管理三块，

## 1. 项目架构（现状）

### 1.1 五层结构与数据流

```
DSH Web（浏览器插件 UI，src/web/*）
   │  HTTP（24 端点，loopback-only）+ SSE 事件流
   ▼
src/plugin.ts（宿主半：路由/工具/announcement）
   ▼
src/pod-service.ts（宿主门面：版本锁 / 单活跃会话 / 原子发射 / 记忆+定时宿主）
   ▼
MissionOrchestrator（src/core/orchestrator.ts，每 mission 一个实例）
   │  规划(planner+代码裁决) → 派发(协商+路由) → 质量门(Verifier) → 审批卡 → 合并
   ▼
WorkerBackend（src/workers/*，vendor adapter）→ 真实 CLI 进程
   │    claude / codex / opencode / ark / remote / demo（脚本演员）
   ▼
git worktree（<repo>/.pod-worktrees/<mission>-<slot>，员工隔离视角）
```

- **持久化**：`~/.dsh/pod`（磁盘唯一事实源）。双后端：JSON 文件（`store.ts` JsonStore）
  与 SQLite（`sqlite-store.ts`，mission/task/event 整对象 JSON 行落库，零 schema 迁移）。
- **不变量**（AGENTS.md，代码强制）：① LLM 提议、代码裁决；② 原始事件永不进 commander
  上下文（`store.appendEvent` 唯一通道）；③ 审批/收集/合并只走 `pod_approve`/`pod_collect`/`apply_patch`；
  ④ 员工进程三道防线（charter + `--allowedTools` 白名单 + 路径校验）；⑤ 路径白名单（防 `..`/绝对路径/盘符）；
  ⑥ 预算双闸（tokens 权威 + equiv_usd 估算）。

### 1.3 员工（agent）是什么

每个员工 = 一个带独立 git worktree、独立会话（档位）、被任务 spec 驱动、以 MISSION_REPORT
交付的 **CLI 进程**。它不能直接合并任何东西（写盘前确认是引擎硬边界）。worker 之间**不点对点
对话**——所有协作经编排器「规格注入 + 事件审计」进行（实现→审查的 diff 宿主注入、人工→agent
的 steer 队列、换人交接四件套）。Commander 是宿主内 DSH agent 会话（`commander.ts`），经
pod_* 工具驱动编排，不是 worker。

## 2. Token 开销（实测 + 控制手段）

### 2.1 计量模型

- **双列**：tokens（CLI 实测，权威列）+ equiv_usd（公共 API 价 × tokens，价目表版本号标注；
  无价模型 price_known=false 不编造，CR-01-5）。
- **预算双闸**：token 上限（主）+ 美元上限；派发前 `estimateTaskCostUsd` 短路，剩余不足不派发
  并发 `budget_short_circuit` 事件；超限插件层自动 pause + 告警。
- **归因**：账本条目按 slot/task/model 记录；`by_stage` 按任务类型（plan/implement/review/…）聚合。

### 2.2 实测成本锚点（BAKEOFF.md / 审计-2026-08-30）

| 场景 | 量级 | 来源 |
|---|---|---|
| 单 agent 写码任务 | 68K~242K tokens / 194s~1054s | bakeoff 主对比 |
| Pod 全链（实现+审查+审批） | 132K~349K tokens（+37%~155%） | 同左 |
| **review 上下文注入（修复前）** | 单次派发可达 **12 万字符 ≈ 30-40K tokens**；重试 3 次付 3 倍 | 审计 P0-1 |
| `task_context` 事件（修复前） | 每次派发全量 8KB 落盘，重试重复累积 | 审计 P0-2 |
| commander 每轮 LLM 调用工具定义 | 固定 3-5K tokens（阶段大半工具用不上） | 审计 P0-3 |
| 档位 B 会话复用失效（修复前） | 每次重复付上下文重建 token + 丢跨任务连续性 | 审计 P0-4 |
| 记忆 A/B（10 对） | 记忆组平均省 5,602 tokens/任务（7/10 胜）；wall 无显著收益 | BAKEOFF §3-4 |
| 措辞 A/B（5 对 10 跑） | 软化无回归、无显著收益（Δtoken −45 ≈ 0，符号检验不显著） | BAKEOFF §6 |
| P0-2 静态前缀（2026-08-31） | 静态脚手架 byte-稳定、占完整 prompt ~95%（~397/~419 tok）；cache 命中率经 ledger `cache_read_tokens` 实测列观测 | `scripts/measure-prompt-prefix.mjs` |

### 2.3 控制手段（已上线）

1. **review 注入分级上限 + hunk 两级加载（P1-5）**：`MAX_REVIEW_SPEC_CHARS=2000` /
   `MAX_REVIEW_SUMMARY_CHARS=1500`；diff 走 `diff-hunks.ts` 两级——变更地图恒全量（第一级，很小）+
   相关 hunk 按预算装入（第二级），预算外保留地图、审查者经 fs-browse 主动拉取；
   `task_context.review_truncated_hunks` 记录被切 hunk 元数据。
2. **task_context 覆盖而非追加**：同一任务只保留最新一份（重试不再重复落盘 8KB）。
3. **档位 B 会话复用生效**：`session_ref` 从 workers 写回 slot；档位 C 刹车（占用≥70% 重建 +
   注入结构化摘要）防会话撑爆窗口。
4. **planDelivery 矩阵**（queue/memory × 三档）确定六种投递动作。
5. **team/措辞不烧钱**：P1 feedback 环用确定性名册反馈（零额外 LLM）；bakeoff 结论不支持
   再为措辞投入。

## 3. Harness 间通信协议

### 3.1 Worker ↔ 编排器（headless CLI 协议）

- **入**：prompt 经 stdin（短固定 argv：`claude -p --output-format stream-json --verbose
  --include-partial-messages --disable-slash-commands --bare`，模型/会话档位/白名单/权限模式
  走 argv）。
- **出**：stdout 逐行 stream-json（assistant 文本块 → 进度；工具调用 → tool_call 有界预览；
  result 事件 → MISSION_REPORT + usage 实测）。stderr 尾随（最后 ~12 行）作失败根因（401 等）。
- **完成判定**：退出码 + 结构化输出（result.is_error 优先于退出码，不猜）。
- **会话档位**：transient 每任务新进程；per-mission 用 `--session-id`/resume；auto-reset 达
  阈值销毁重建。
- **kill**：进程树终止（Windows taskkill /T /F；POSIX 进程组 SIGTERM）。

### 3.2 对外协议面

| 面 | 路径/形态 | 说明 |
|---|---|---|
| A2A | `/.well-known/agent-card` + `/a2a/sendMessage[Stream]` + JSON-RPC | 外部把整个 Pod 当一个 agent 驱动；Task=mission；SSE 流式事件；loopback NoAuth |
| IM | Slack / 飞书（`channel-im.ts`） | 人机指令通道：验签 + 时间窗 + 重放去重 + 出站净化白名单；回复复用审批门 |
| MCP | `mcp-server.ts` | 把 pod_* 工具反向暴露：Claude Code 等外部 agent 可驱动 Pod；stdin transport；
  Pod 作客户端时经 `mcp-gateway.ts`，接入前跑 `scanToolDescriptions` 静态审查（防 tool poisoning） |
| HTTP | 24 端点（`routes.ts`） | status/events/stream/launch/steer/approve/deny/plan/missions/dispatch/resolve/rules/pause/resume/abort/task pause-resume/reassign/memory/memory-correct/cron/assets/fs-browse |
| SSE | `/events/stream` | 事件流（replay + 增量），id 精确游标；轮询兜底 |
| 事件面 | `store.appendEvent` 唯一通道 | worker_progress（reply_id+seq 聚合重建）、agent_relay、task_question、approval_*、plan_* 等 |

### 3.3 员工间协作的「协议」= 编排器居中代理

- **实现→审查**：审查任务 spec 由宿主注入 diff 区间 + 产物摘要（最小上下文，审查者无需仓库权限），
  `agent_relay` 事件留痕（对话可见 A→B 行）；常规流转补 `handoff_created`（`H-REVIEW-*`，带 verify 清单）
  ——与 reassign 换人同走协议面，前端可呈现「谁传了什么给谁」（审计 P1，不改传递机制）。
- **人工→agent**：steer 队列，下次派单必带（不打断在途进程，CR-01-2）。
- **换人**：交接五件套落盘 + 事件审计，任务置 ready 重派（`pod_reassign`）。
- 刻意不做点对点自由对话：不可审计/不可重放/不可预算化。

## 4. 上下文管理

### 4.1 会话三档（`session-tiers.ts`）

| 档 | 语义 | 判定 |
|---|---|---|
| A · transient | 每任务新进程，零跨任务上下文 | codex/dsh/ark/opencode 默认 |
| B · per-mission | 同员工同 mission 复用会话（--resume/--session-id） | claude 默认；`session_ref` 写回生效 |
| C · auto-reset | 会话占用达阈值 → 销毁重建 + 注入结构化摘要；**阈值按内容密度自适应**（P1-2：review diff 密集 50%，常规 70%） | `needsAutoReset` + `resetThresholdFor`：凡复用会话达阈值即重置 |

- 占用计算：`sessionCtxUsage = (tokens_in+out − session_base_tokens) / window_tokens`——
  按**当前会话增量**算（重建后归零，累计消耗是成本事实不归零）。
- 重置摘要（P1-1 ACE 化 delta 账本）：任务完成时由 Generator 入账一条 Rich fact 条目
  （commit/测试结果/决策，只写一次），重置时 Reflector 只渲染 active 条目（不重扫不重写）；
  被重做推翻的条目标 superseded 保留留痕（Curator）。**不含原始对话与叙事**（S5），
  但测试证据/决策不再丢失（旧整写摘要只留 2/5 字段）。
- 重置触发第二维（P1-2，Context Rot）：`slot.content_density_pct` 记录最近派发的
  「相似干扰项密度」（review diff 注入占比），密度 ≥60 → 50% 提前重置；
  implement spec/指令异质密度低 → 维持 70%（不牺牲会话复用收益）。量化脚本
  `scripts/measure-reset-threshold.mjs`；完整阈值 bakeoff 扫 50/60/70/80% 待真实 mission 观测。
- 重置后 verbatim 近期窗口（P1-3）：重置摘要后注入在途任务最近 N=3 条原始事件
  （worker_progress / steer_queued / task_question / agent_relay）逐字，按 task_id 过滤
  → 任务结束自动清空，不跨任务不叙事（S5）；防「重置后断片」（~38 tok，<摘要 1%）。

### 4.2 派发时的上下文组装（Context Builder）

每次派发，编排器把以下按序拼进 spec（`task_context` 事件落盘 = 实际发出上下文的唯一事实源，
前端上下文查看器据此展示）：

1. **任务 spec 基线**（planner 生成或 launch 显式）；
2. **团队宗旨**（本轮 P0-B）：mission `tenets` 前置注入（3-5 条价值观锚点，有才注入，
   `tenets_injected` 标注）；
3. **档位 C 重置摘要**（占用达标时）；
4. **review 最小上下文**（仅 review 任务：diff 上限 40K 字符 + 规格截断 + 产物摘要，排除实现者叙事）；
5. **steer 排队指令**（`steer_injected` 标注）。

prompt 层（`buildTaskPromptSegments`，P0-2）另把**静态脚手架**（charter/fallback + 交付纪律 + 报告
schema）连续前置且 byte-稳定（同 mission 同类型任务逐字节一致），动态段（任务头/工作目录/审查块/
简报/交接）置尾——为 prompt cache 提供可命中前缀；交付纪律不内联任务 id（commit 前缀由 worker
从任务头解析），代价是纪律文本失去具体 id，换来前缀稳定。

### 4.3 长期记忆（主动策展，非自动摘要）

- **设计**：员工/commander 通过 `pod_mem_write/query/correct` 主动策展；类型化关系
  （supports/contradicts/derived-from）连成图谱；后台 reflection 合并/关联/剪枝。
- **CR-07-4**：只注入与当前任务相关记录；不自动摘要会话日志；蒸馏输入是策展记录。
- **归属粒度**（本轮 P1-2）：个体 = `owner_slot_id`；团队 = `team:<mission_id>`（commander 收口，
  工具描述已标注约定）。
- **运行时注入（N2，已接线 2026-08-31）**：worker 无需 `pod_mem_*` 工具——派发时编排器
  按「槽位 + 团队(team:<mission>)」拉相关记录（importance≥3、各取前 4、去重有界 ≤6、
  content_ref 指针式截断 160 字符），注入 `## 相关记忆` 区块（`task_context.memory_injected` 标注）。
  写/查仍走 commander 主动策展（CR-07-4）。

### 4.4 措辞与语义锚点（本轮 P0-A）

- `buildPlannerSpec` 与 `buildTaskPrompt` 脚手架已从「必须/禁止」威胁框架改为契约事实 + 正面引导
  （安全纪律靠代码三道防线，不靠 prompt）。
- Bakeoff 结论：软化无回归、无显著收益；不追加 spec 包装投入（BAKEOFF §6）。
- **P1-6 pinned 层不变量**：tenets / 交付纪律（`COMMIT_DISCIPLINE`）/ 身份回退（`FALLBACK_IDENTITY`）/
  路径白名单提示「永远逐字、永远最前」，任何压缩/重置/delta 摘要/记忆注入不得改写。
  不变量测试 `tests/pinned-invariants.test.ts`（5 用例，TypeCompact 防 governance decay；与 P0-2 前缀 hash 合并）。
