# 桌宠动作规格 v2（六角色 × 十二动作）

> 定位：[桌宠角色生产规格.md](./桌宠角色生产规格.md)（v1，三视图→帧动画）之上的**动作层扩展规格**。
> v1 解决「一个角色长什么样、怎么切成帧」；v2 解决「六位舱员各有什么元素、十二个动作怎么演、
> 每个动作对应驾驶舱哪条事件」。素材仍按 v1 的 frames2d/sprite2d 双契约产出，本文件不改动
> 任何 v1 历史决策，只做轨道集扩展。
>
> 配套交互预览器：[桌宠动作规格-v2-原型.html](./桌宠动作规格-v2-原型.html)（浏览器直接打开，
> 六角色 × 12 动作全可演示，含分镜步进与生产参数）。

## 1. 设计原则

1. **全员形态一致、元素不同**：六位舱员共用同一套身体骨架（二头身贴纸风、白描边、兜帽小人、
   死鱼眼半睁表情），只替换六件识别物——帽顶饰 / 帽耳 / 背后尾饰 / 配色 / 胸章 / 动作道具。
   一套骨架 × 六套皮肤，素材可分层生产（12 套动作骨架 × 6 套皮肤贴片）。
2. **动作即事件**：十二个动作不是装饰，每个动作绑定 dsh-pod 的真实状态/事件词汇
   （`slotPhase()` 七相位 + 五条事件窗口轨道），桌宠是驾驶舱的「看得见的化身」。
3. **error 是唯一带文字的动作**：其余所有道具一律图形符号化（提示符、Z 字、窗口圆点都用
   path 画，不用 `<text>`），保证小尺寸可读、无字体回退风险。
4. **同款动作只换色**：idle / error / notification / sweeping 的清扫物 / carrying 的箱子骨架
   等全员同款编排，差异只在各自品牌色，降低素材量。

### 2.2 元素矛盾的统一裁决（v2 拍板）

- **终端·苏苏的「花系 × 终端系」混用**（花锤+代码块、六瓣花球 vs 终端符、终端窗）→ 统一为
  **「代码花」视觉语言**：花瓣=紫蓝渐变外形，花蕊=终端提示符（荧光绿图形符号，面积≤5%），
  容器=圆角窗口描边（终端窗即整朵花的窗口化封装）。全部道具共享同一语言。
- **六边·六六的「三横杠」vs 六边系** → **「外壳静止、内部运转」**：thinking 时六边外壳不变、
  内部出现三道加载横杠（六边形水平切片形态），语义=模块运算中，与黑白机械主题同源。
- **idle「扶镜」的载体** → v2 拍板为**扶帽檐**（兜帽替代镜），保持全员无眼镜的既定形态；
  理由：参考图与 v1 角色均无眼镜，加镜破坏「形态一致」原则；动作语义（推一下头部识别物、
  回正）不损失。若后续要眼镜变体，作为可选皮肤贴片追加，不进 MVP。
- **猫「渐变」色相** → **粉→淡紫渐变**（#EE7FA9→#C99BE0）+ 猫瞳绿点缀，与星花（暖橙）、
  终端（蓝主导的紫蓝）拉开色相距离。

## 3. 十二动作总表（动作 × 事件映射）

前 7 行对齐 `pet-room.ts slotPhase()` 既有的七相位词汇（旧角色不注册新轨道则走引擎 fallback，
行为完全不变）；后 5 行为 v2 新增的事件窗口轨道。

| # | 动作 | 轨道名 | 类型 | 时长 | 触发事件（dsh-pod 词汇） | 分镜要点 |
|---|---|---|---|---|---|---|
| 01 | 发呆 ★ | `idle` | 循环 | 4.4s | slot idle / 无 mission | 呼吸 → 眨眼×2 → 扶帽檐 → 歪头（影子同步微倾）→ 回正 |
| 02 | 思考 | `think` | 循环 | 3.4s | running（非 tool_call）· commander 规划 | 气泡弹出（鲸尾/八角星/终端符/三横杠/猫脸/Z）+ 托腮 + 头微歪 |
| 03 | 打字 ★ | `type` | 循环 | 1.2s | running + progress text 流式（thinking 相位细化，P2 接线） | 键盘滑入 → 键帽波浪浮起 → 手臂交替 → 身体前倾点头 |
| 04 | 建造 | `build` | 循环 | 1.3s | running + tool_call（写文件/装依赖/构建） | 举锤蓄力 → 敲击 → 主题方块（冰晶/木/代码/模块/文件夹/科技块）弹跳+火花 |
| 05 | 抛球 | `juggle` | 循环 | 1.7s | parallel ≥ 2 并行执行窗口 | 三球相位差 1/3 弧线循环，双臂上下跟随，视线跟随 |
| 06 | 指挥 | `conduct` | 循环 | 2.1s | Commander 派单/编排 | 指挥棒画弧，2 个主题子Agent（1/3 尺寸迷你自我复制）随棒拍浮空跳动 |
| 07 | 报错 ★ | `error` | 一次性 | 3.2s→保持 | blocked / escalated / slot error / 预算熔断 | 品牌色 ERROR 牌坠落（唯一文字）+ 冒烟 → 垂头 → 蹲下抱头发抖，停在末帧直到相位离开 failed |
| 08 | 庆祝 ★ | `happy` | 一次性 | 2.8s | mission done / 质量门通过 / 合并成功 | 蓄力下蹲 → 起跳 → 最高点自有形彩片（水滴/星芒/花瓣/六边/爪印/闪电）炸开 → 落地 → 双臂欢呼 |
| 09 | 通知 | `notify` | 循环 | 4.4s | awaiting_approval 审批卡待批 / 桌面通知 | 盾牌（品牌色+对勾）举起 + 权限气泡弹出 + 小幅晃动 + 指尖点气泡发光环 |
| 10 | 扫地 | `sweep` | 循环 | 1.7s | 上下文压缩 / session 70% 重置摘要 | 自有色扫帚扫三下，像素块+碎纸滑向簸箕（清理上下文语义） |
| 11 | 搬运 | `carry` | 一次性 | 3.6s | 交接四件套 handoff / reassign 换人 | 蹲下抱箱（印自有标志）→ 扛上肩 → 左右腿交替走 → 放箱 |
| 12 | 睡觉 ★ | `sleep` | 循环 | 9.2s | mission paused / 空闲超时挂起（v1 可选轨道，事件窗口点名） | 打哈欠 → 打盹点头×2 → 蜷睡（自有形睡眠气泡漂浮）→ 鼠标惊醒弹起 |

★ = 四个基础必做动作（idle / error / happy / sleeping）+ 打字（键帽浮起），构成 MVP 优先级。

### 3.1 与 v1 六轨的承接关系

| v1 轨道 | v2 承接 | 说明 |
|---|---|---|
| `idle` | `idle` | 同名直传 |
| `work` | `think` + `type` | work 拆分为思考（无 progress text）与打字（流式输出）两个语义位 |
| `drag` | `type` + `build` | drag 的工具调用语义由 tool_call 事件细分：文本流→type，工具执行→build |
| `success` | `happy` | 同语义更名（语义化轨道名） |
| `fail` | `error` | 同语义更名 + 增加末帧保持（蹲抱到相位解除） |
| `angry` | `angry`（保留） | 交叉审查对峙编排（reviewDuels）继续使用，不进十二动作表 |

### 3.2 驱动口径（编排层）

分两层，诚实对齐现行引擎：

**第一层：7 相位轨道由 `slotPhase()` 既有逻辑直驱**（只需 pet.json v2 的 `phases` 段换轨道名，
引擎零改动）：`idle→idle`、`thinking→think`、`tool→build`、`review→think`、`waiting→idle`、
`done→happy`、`failed→error`。旧角色不注册新轨道则走既有 fallback，行为不变。

**第二层：事件窗口/相位细化轨道由编排层点名播放（P2 接线）**：

| 轨道 | 点名时机 | 与现行相位的关系 |
|---|---|---|
| `type` | 相位=thinking 且 latestEventKind==='text' | thinking 的流式细化（现行 text 落 thinking 相位，需在 VendorPet 传入 latest.kind 细分） |
| `juggle` | parallel ≥ 2 并行批次开跑窗口 | 叠加表现 |
| `conduct` | Commander 派单/编排窗口 | 叠加表现 |
| `notify` | awaiting_approval 审批卡弹出窗口 | waiting 相位的升级表现 |
| `sweep` | 上下文压缩 / session 70% 重置摘要窗口 | 叠加表现 |
| `carry` | reassign 交接四件套落盘窗口 | 叠加表现 |
| `sleep` | mission paused / 空闲超时 | v1 可选轨道；现行 paused 落 waiting 相位，点名后覆盖 |

窗口结束回 fallback。P0/P1 阶段桌宠先按第一层 7 相位运行，第二层随 P2 接线逐步点亮。

## 4. 生产参数（沿用 v1 契约，零引擎改动）

| 维度 | 口径 |
|---|---|
| 轨道帧数 | 循环轨 4–8 帧；一次性轨 3–5 帧 + fallback idle |
| 帧尺寸 | 192×208 webp 透明底（或整倍率），帧间头部大小与地平线一致 |
| 时长解析 | frameMs[] > 文件名 _<ms> 后缀 > defaultFrameMs（缺省 200ms） |
| phases 映射 | pet.json v2 phases 段（见 §5 模板） |
| fallback 链 | 未注册轨道 → idle；error 末帧保持到相位解除 |
| 降级 | prefers-reduced-motion 全轨道静态化 |

## 6. 分镜细则（核心五动作）

以下为 MVP 优先实现的五个动作分镜（时长/缓动/循环属性），其余七个动作的分镜见
交互预览器（选动作后右侧「当前动作 · 生产参数」卡）。

### 6.1 idle 发呆（循环 4.4s）

| 步 | 时间窗 | 缓动 | 要点 |
|---|---|---|---|
| 呼吸 | 0–2.2s ×2 | sine | 身体 scaleY 1↔1.022；影子 scaleX 0.97↔1.03 同步 |
| 眨眼×2 | 1.2s / 3.7s | ease | 眼睑 0.12s 全闭回半睁 |
| 扶帽檐 | 1.9–2.9s | ease-out | 手臂抬至帽檐轻推，帽顶饰随动 |
| 歪头 | 3.2–4.1s | ease-out-back | 头 rotate 9°，影子 translateX 5px + scaleX 1.045 |
| 回正 | 4.1–4.4s | ease-in-out | 回基准；尾饰/帽耳滞后 0.1s、幅度 1/3 随动（全局规则） |

### 6.2 typing 打字（循环 1.2s；入姿 0.2s 一次性）

键盘滑入（0.5s back 过冲）→ 键帽左中右依次浮起 −6px（相位差 0.1s）→ 手臂交替 rotate ±7°
→ 身体前倾 2.4° 点头。键盘配色六角色各异（蓝白水波 / 米白橙 / 紫蓝渐变 / 黑白机械 /
粉紫渐变 / 蓝光背光）。

### 6.3 error 报错（入场 1.2s 一次性 + 烟雾循环 + 末帧保持）

品牌色 ERROR 牌 0.3s 弹出（overshoot）→ 帽侧冒烟（1.6s/团 错相循环）→ 垂头 0.4s →
蹲下抱头 0.5s → 颤动保持（±1.5°/0.5s）直到相位离开 failed → 恢复 0.4s 弹回 idle。
ERROR 文字路径化（图形符号），渲染宽 <64px 时降级为「!」符号牌。

### 6.4 happy 庆祝（一次性 2.3s → fallback idle）

蓄力下蹲 0.3s（scaleY 0.90）→ 起跳 0.35s（−40px, scaleY 1.08）→ 滞空点 8–12 片自有形彩片
360° 放射（随机向量 24–40px + 旋转 180–360° + 重力回落，0.9s）→ 落地 0.25s（scaleY 0.88 回弹）→
双臂上举欢呼 0.8s（挥 2 次 + 原地小跳 ±4px×2）。

### 6.5 sleeping 睡觉（入眠 2.6s 一次性 + 蜷睡循环 + 惊醒 0.85s 一次性）

打哈欠 0.8s（头后仰 5° + 嘴张开）→ 打盹点头 ×2（1.2s）→ 蜷坐抱膝（scaleY 0.80，呼吸循环
2.4s）+ 3 枚自有形睡眠气泡错相上飘（水泡/星形/窗口/六边/爪印/Z字泡）→ 鼠标指针滑入 →
惊醒弹起 0.35s（−18px, 眼瞪圆）→ 气泡破裂 0.15s → 落地回 idle。
