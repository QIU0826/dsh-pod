> 2026-09-13 建立。此前该清单只在 `demo-data/pet-assets/README.md`（**未入库**，`demo-data/` 被
> `.gitignore`），且内容与事实漂移（表列 7 个角色、实际 9 个）。本文件是**入库的角色包事实源**：
> 只入库文档，**不入库二进制资产**（帧/主视觉是生成产物，见「生产管线」）。

## 生产管线

两条自产管线（都依赖 Chrome/Edge 无头 CDP 渲染）：

| 管线 | 脚本 | 状态 |
|---|---|---|
| **贴纸线** | `scripts/pet-assets-sticker.mjs` | **现役**——全部 8 个角色都走这条 |
| SVG 平涂线 | `scripts/pet-assets-generate.mjs` | **已退为历史**，不要再跑（会覆盖贴纸线产物） |

贴纸线流程：SVG 主视觉 → 去白底 → 重建白描边 → 参数化派生六轨 21 帧。
设计迭代可用快速看图回路：`node scripts/pet-assets-sticker.mjs --preview <角色id>`（只出 PNG，不跑去底/描边/六轨）。

产物（默认落 `assets/pet/`，**入库并随包发布**——全新 clone 即有品牌娘，无需先跑生成脚本）：

```
assets/pet/<id>/<track>/<short>-pet-<track><n>.webp   # 六轨 21 帧（192×208 透明底）
assets/pet/<id>/hero.webp                             # 贴纸主视觉（定稿/换装参考）
assets/pet/<id>/pet.json                              # 显式帧表清单（六轨 + phases 映射）
```

**服务解析顺序**（`standalone/server.ts`）：`<dataDir>/pet-assets/**`（用户覆盖）优先 →
`<pkg>/assets/pet/**`（随包内置）兜底；两者都没有 → 404，由客户端逐级回落内置鲸鱼娘。

六轨 = `idle4 / work4 / drag4 / success3 / fail3 / angry3`（非循环轨 `loop:false + fallback:'idle'`）。

## 已知边界（如实记录）

1. **资产入库并随包发布** —— 角色包在 `assets/pet/`（**不在**被 ignore 的 `demo-data/`），
   随 `package.json` 的 `files` 一起发布；全新 clone / 安装即可看到品牌娘，不必先本地生成。
   （重生成后需一并提交 `assets/pet/` 的二进制。）
2. **生成不可 CI 复现** —— 管线依赖 Chrome CDP + 手写 SVG，不进 CI；资产本身已入库，故 CI 不需要它。
3. **three-views.webp 口径** —— 贴纸线不产出该文件；部分角色目录里的是 SVG 平涂线时期的遗留，
   仅供参考、不参与运行时。
